做 Workers 專案時，設定值大致有三種，放的地方不同。

## 三種設定值

| 類型 | 例子 | 放哪裡 |
|---|---|---|
| 公開設定 | 網站名稱、功能開關 | `wrangler.jsonc` 的 `vars`，可以進 git |
| 機密 | API 金鑰、簽章用的密鑰 | `wrangler secret put`，不進 git |
| 本機開發用 | 測試用的假金鑰 | `.dev.vars`，加進 `.gitignore` |

判斷標準很簡單：**洩漏了會不會出事**。會，就是機密。

```bash
# 寫入機密，值不會出現在檔案裡
npx wrangler secret put MY_API_KEY
```

程式裡從 `env.MY_API_KEY` 讀取。

## 我自己守的規則

- `.dev.vars` 與任何 `.env` 檔一律在 `.gitignore`，並且一開始建專案就先加，不要等有檔案才加。
- 專案裡放一份不含真值的範例檔，例如 `.dev.vars.example`，讓自己或別人知道需要哪些變數。
- 前端程式碼裡不放任何金鑰。能被瀏覽器載入的東西，就等於公開。需要呼叫第三方服務時，由 Worker 代為呼叫。
- 提交前看一眼 `git diff`，特別注意新增的檔案。

## 如果不小心提交了

1. **先作廢金鑰**，到服務提供者那邊重新產生。這是第一步，也是唯一真正有效的一步。
2. 再處理 git 歷史。把檔案從歷史裡清掉並不保證安全，因為可能已經被別人複製或被爬蟲收走。
3. 檢查相關帳號有沒有異常使用紀錄。

順序不要反過來：很多人先花時間清歷史，金鑰卻一直是有效的。
