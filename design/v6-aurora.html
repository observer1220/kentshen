資安前端

前端的資料，真的保護得了嗎？

把資料藏在 API 後面，只能提高隨手複製的門檻，無法真正阻止別人拿到。這篇說明這個物理限制，以及我實際的做法。

台灣百岳地圖上的山岳資料，不是放在網站的靜態檔案裡，而是透過一支後端 API 提供。有人問過我：這樣是不是就保護了資料？我的答案是：只保護了一部分，而且要誠實說清楚是哪一部分。

這樣做有什麼效果

  • 資料不再是一個「一個網址就找得到」的檔案。
  • 不會被搜尋引擎當成獨立的頁面索引。
  • 不會被隨手寫的爬蟲撿走。

這樣做沒有什麼效果

只要地圖需要顯示這些資料，瀏覽器就一定會收到完整的內容。這是前端網站的物理限制：

凡是要顯示給使用者的資料，使用者的瀏覽器就必然拿得到。

所以這個做法提高的是「隨手複製」的門檻，而不是做到「真正無法取得」。我在專案的說明裡也是這麼寫的，沒有把它說成資料保護。

為什麼不乾脆加密

解密的金鑰也得放在前端，否則瀏覽器無法解密。真正能保護資料的做法只有一種：不把它送到瀏覽器。
